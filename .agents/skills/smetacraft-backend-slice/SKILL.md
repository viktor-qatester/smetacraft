# Backend vertical slice SmetaCraft

До кода сверяй утверждённый сценарий и границы с `docs/ROADMAP.md`, `AGENTS.md`, `docs/FRONTEND_MODULES.md`, `docs/regression-baseline.md`, `js/app/project.js`, `js/app/boot.js` и тестами. Укажи путь запроса от действия в браузере через API до видимого ответа, формат данных и отказ при недоступном сервере. Реализуй только согласованный сценарий; выбор стека и хранилища обоснуй для этого сценария.

Сохраняй расчёт в `js/core/*.js` и существующие строки, количества и суммы ведомости. JSON-проект остаётся `smetacraft-project` версии 1; клиентский импорт, экспорт и ключ `smetacraft_project` сохраняют поведение. Серверный ответ не должен незаметно заменять проект или очищать `localStorage`. Перенос проектов, постоянное закрытое файловое хранилище, учётные записи и коммерческие ограничения требуют отдельного scope.

Для каждого API зафиксируй метод, путь, допустимый body, лимит размера, успешный и ошибочные ответы. Проверяй вход на серверной границе до использования: типы, формат, версию и ограничения, соответствующие роли endpoint. Ограничивай доступ к локальному серверу согласно согласованной модели угроз; не выдавай содержимое файлов за пределами статического корня и не отражай пользовательский текст как HTML. Ошибка сети, неверный ответ и отказ сервера должны оставлять текущие форму, ведомость и локально сохранённый проект пригодными к работе.

Добавь тесты реального HTTP-пути: успешный запрос, неверные метод и маршрут, повреждённый или слишком большой body, неверные типы и версия, отказ без побочных эффектов. Запусти golden, security и project-model наборы без перезаписи `tests/golden.json`; проверь синтаксис и `git diff --check`. Через HTTP в браузере пройди согласованный сценарий и отказ сервера, затем контрольный расчёт с прежними строками и итогом ведомости. Перед приёмкой проверь diff на выход за scope и покажи запуск, ответы API, результаты тестов, браузерную проверку и способ отката. Commit, push, PR и deploy — только по отдельному разрешению владельца.
