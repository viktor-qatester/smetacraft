# Предметное ревью изменений

Прочитай задачу и её критерии, `AGENTS.md`, `PRODUCT_SPEC.md`, `docs/regression-baseline.md`, затем текущий diff и релевантный код. Отдели уже существующие особенности от изменений в diff. Не объявляй дефект без воспроизводимого пути вход → функция → строка/сумма или security sink.

Проверь: затронут только согласованный модуль; нет правок готовых расчётных модулей и формул вне согласованного scope; единицы, запасы, округление закупки и цены согласованы; строки `name/netLabel/k/orderLabel/cost` и сводная сохраняют контракт; JSON v1, `localStorage` и явно заданный `opening.locked` совместимы; импорт не меняет DOM при отказе; пользовательский текст не проходит через HTML-парсер. Проверь состав staged/working diff, включая отсутствие случайно добавленных пользовательских файлов и изменений `tests/golden.json` без разрешения.

Запусти релевантные golden/security тесты и `git diff --check`, сопоставь с независимым ручным расчётом, если затронуты материалы. Для браузерных свойств укажи, что Node DOM-модель их не подтверждает.

Выход: сначала конкретные findings по приоритету с файлом/строкой, входом, фактическим и ожидаемым результатом; затем пройденные проверки и остаточный риск. Если findings нет, скажи это прямо. Не исправляй, не коммить и не публикуй в режиме ревью без отдельной задачи.
