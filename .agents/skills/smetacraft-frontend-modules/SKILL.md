# Frontend-модули SmetaCraft

Применяй вместе с `smetacraft-phase-orchestrator` после утверждения конкретного шага Phase 5. Сверь `docs/ROADMAP.md`, `AGENTS.md`, карту системы, `index.html`, `js/core/*.js`, `js/ui/*.js`, `js/app/*.js` и тесты.

Для одного пользовательского потока составь карту: DOM-элементы, чтение и проверка ввода, состояние, обработчики, запуск, вызовы Calculation Core и запись результата. Выделяй только согласованные части. Явно определи вход модуля, зависимости и порядок загрузки; один источник состояния должен остаться один. Не меняй формулы и возвращаемые строки `name/netLabel/k/orderLabel/cost` при переносе UI.

Сохраняй внешний вид, клавиатурное и печатное поведение, безопасную запись пользовательского текста в DOM, JSON v1, `localStorage` и анкеты. Если поток затрагивает данные проекта, применяй `smetacraft-project-json`; если расчётный результат — `smetacraft-formula-audit`.

Обнови `tests/runtime.cjs`, чтобы он исполнял настоящие файлы приложения в порядке браузерной загрузки без копирования формул. Проверь golden, security и project-model наборы, затем через HTTP открой страницу и пройди затронутый поток, сводную, новый проект и восстановление проекта там, где они пересекаются. Сравни строки и суммы с прежним эталоном; `tests/golden.json` не переписывай ради зелёных тестов.

На приёмку покажи границу переноса, diff, результаты тестов и браузерной проверки, отличия поведения либо их отсутствие. Commit/push — по разрешению владельца; Phase 6 не начинай автоматически.
