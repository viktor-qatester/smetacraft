# Оркестратор фаз SmetaCraft

При начале фазы прочитай [дорожную карту](../../../docs/ROADMAP.md) и [карту системы](references/current-system.md), затем сверь их с актуальными `AGENTS.md`, `README.md`, `PRODUCT_SPEC.md`, `docs/regression-baseline.md`, кодом `index.html`, тестами, статусом Git и последними коммитами. Сначала проверь, что предшествующая фаза действительно реализована и принята: план или слова о «трёх фазах» сами по себе этого не доказывают. Если цель фазы не задана, предложи scope по дорожной карте и пометь допущения; вопрос владельцу задавай вместе с готовым планом, а не до него.

1. Установи цель фазы, границы, затронутые разделы и файлы, неизменяемые контракты и проверяемые критерии завершения. Не добавляй соседние задачи из старых документов.
2. Прочитай и применяй только нужные предметные скиллы: [формулы](../smetacraft-formula-audit/SKILL.md) для расчётов, [JSON](../smetacraft-project-json/SKILL.md) для сохранения и импорта, [тесты](../smetacraft-regression-tests/SKILL.md) для проверок, [ревью](../smetacraft-domain-review/SKILL.md) для финального diff, [frontend](../smetacraft-frontend-modules/SKILL.md) для Phase 5, [backend slice](../smetacraft-backend-slice/SKILL.md) для Phase 6.
3. До реализации покажи владельцу конкретный план: исходная база, изменения по файлам, ручной контрольный расчёт, автоматические и браузерные проверки, риски, критерии приёмки. Остановись для подтверждения фазы. Если именно этот план уже утверждён, не спрашивай повторно.
4. После подтверждения выполни план автономно по одному модулю за раз; проверь результат и исправь регрессии в согласованном scope. Не требуй подтверждения каждого технического шага. Существенное расширение фазы согласуй отдельно.
5. Покажи diff и доказательства сохранения расчётного контракта. Commit, push, PR и deploy выполняй только при отдельном разрешении. После принятой фазы проверь скиллы через [skill-maintenance](../smetacraft-skill-maintenance/SKILL.md), если изменились пути, контракты или процесс. Не начинай следующую фазу автоматически.

Явные указания владельца и `AGENTS.md` имеют приоритет. Готовые расчётные модули `js/core/*.js` и UI в `js/ui/*.js` и `js/app/*.js` не меняй вне согласованного scope.
