# Публикация SmetaCraft

Одна команда после будущих правок, из корня репозитория:

```
node scripts/publish.cjs
```

Она по порядку:

1. Прогоняет проверки расчётов и безопасности.
2. Делает обычный commit и push в `master`, если есть что сохранять. Force push нет.
3. Ждёт, пока [GitHub Pages](https://viktor-qatester.github.io/smetacraft/) начнёт отдавать этот коммит, и сверяет не только код 200: на странице должны быть плашка тестовой версии, вкладка «Плита», ведомость и номер релиза.
4. Обновляет только проект Docker Compose `vic-smetacraft` на AEZA.
5. Там проверяет тот же интерфейс, расчёт, сохранение тестового проекта и его повторное чтение.

Секреты, `.env`, базы, PDF и `deploy/aeza.local.env` в Git не попадают. Команда их отвергает.

## Как понять, что опубликованы оба места

Откройте две страницы и найдите жёлтую плашку вверху. Строка **«Открыт релиз …»** должна совпадать.

- Страница без сервера: https://viktor-qatester.github.io/smetacraft/
- Приложение на AEZA. Точный адрес зависит от порта в уже существующем `compose.vic.yaml`. На самом сервере номер релиза также отдаёт `GET /api/version`.

GitHub Pages хранит проект в браузере этого компьютера. AEZA хранит проекты в SQLite. Эти данные не делаются одинаковыми. FORNEX команда не трогает: он остаётся прежним окружением на случай отката.

Журнал проверок и статусов: `docs/releases/log.json`.

## Один раз настроить доступ к AEZA

Скопируйте `deploy/aeza.local.env.example` в `deploy/aeza.local.env` и замените `ПОЛЬЗОВАТЕЛЬ` на SSH-логин. Файл локальный, в Git он не входит. Пароль команда не спрашивает: нужен ключ, который сервер уже принимает.

Если ключа с этой машины нет, команда останавливается после GitHub и пишет:

```
В GitHub сохранено, на AEZA не опубликовано
```

Дальше, когда ключ появится:

```
node scripts/publish.cjs --aeza-only
```

Эта команда не делает новый commit. Она берёт уже отправленный `master` и обновляет только AEZA.

## Что происходит на сервере

Каталог: `/srv/vic-workspace/apps/smetacraft`.

Перед заменой кода скрипт пишет копию в `/srv/vic-workspace/backups/smetacraft/дата-время/`:

- `code.tar` — код без `data/` и без `.env`;
- `smetacraft.sqlite` — согласованная копия базы через резервный API SQLite, не обрыв файла;
- `ROLLBACK.txt` — как вернуть эту копию.

Дальше подставляется архив нужного коммита. `data/`, `.env` и `compose.vic.yaml` не перезаписываются. Демонстрационная база не загружается. Миграции — только `node server/db-migrate.cjs`. Перезапуск — только `docker compose -p vic-smetacraft -f compose.vic.yaml`.

Если проверка после замены не прошла, скрипт сам возвращает код и копию SQLite и снова запускает только этот проект.

Если номер схемы в `schema-before.txt` и `schema-after.txt` различается, откат вручную тоже должен вернуть файл SQLite из той же копии. Одного возврата старого кода недостаточно: новая схема не обязана читаться старой программой. Пока схема не менялась, для отката достаточно кода из `code.tar`.

Установщик FORNEX на AEZA не запускается. Чужие контейнеры, сети, тома, firewall, SSH и VPN не меняются.
