### Табу и требования, которые уже обязательны

- Расчёт объёмов, запасов, раскроя и денег — только детерминированный JavaScript. LLM и платные API в формулы не входят. Стоимость расчёта — 0 токенов.
- Формулы, строки и суммы ведомости не меняются «заодно» с переносом кода. `tests/golden.json` не переписывается ради прохождения тестов.
- Бетон +5%, нахлёст арматуры 40d, хлысты 11,7 м, гидроизоляция +15%, трамбование подушки ×1,10. Число стержней: `ceil(пролёт / шаг) + 1`. Контроль: 8,1 м / 200 мм → 42 стержня на одну сетку.
- JSON v1 и `localStorage` (`smetacraft_project`) сохраняются до отдельной миграции. Локальные проекты автоматически не удаляются.
- Импорт PDF/DOCX: только явный текст, evidence, preview, галочки, кнопка «Применить». Цены и валюта из документа не пишутся. AutoCAD без подписей даёт 0 автоподстановок. Факты `needs_review`, `conflict`, `ocr_required` не выбираются.
- Скилл `smetacraft-pdf-facts` прямо запрещает вызывать его для OCR API. План фаз 6–9 запрещает добавлять LLM в расчёты или импорт.
- Сервер не содержит расчётное ядро. API доступен с loopback или с origin из `SMETACRAFT_PUBLIC_ORIGIN`. GitHub Pages — статика, не прод API.
- Секреты и `*.env` в Git не коммитятся (`.gitignore`). Blob и SQLite лежат в `data/*` и тоже не коммитятся.
- Commit, push, PR и deploy — только по отдельному разрешению. Следующая фаза сама не начинается.
- Интерфейс: две колонки, параметры слева, ведомость справа, без декоративного «AI-стиля».

## Текущий функционал

Фазы 0–8 по `docs/ROADMAP.md` приняты. Phase 9 (учёт прав, квоты, аудит, бэкапы, коммерческая готовность) не начата.

### Интерфейс

Разметка и стили — в `index.html`. Скрипты подключаются обычными `<script src>` без сборщика.

Вкладки: «Мой дом», плита, ленточный фундамент, стены, перекрытия, штукатурка, кровля, сводная смета, прайс-лист, проект.

Работает без сервера: ввод параметров, живая ведомость, анкета «Мой дом», прайс (BYN, RUB, USD, EUR, PLN, UAH, KZT, GBP без конвертации курса), сохранение в `localStorage`, экспорт и импорт JSON v1, демо-проект, печать через диалог браузера, встроенные регрессионные проверки на странице.

На разрешённом origin (loopback или Fornex) в блоке «Проект» есть перенос копии на сервер и загрузка PDF/DOCX. На GitHub Pages эти блоки скрыты.

### Математическое ядро

Чистые калькуляторы в `js/core/`, без DOM и без сети:

| Модуль | Функция | Что считает |
| --- | --- | --- |
| `js/core/slab.js` | `calculateSlab` | Плита: бетон, арматура сеток, опалубка, подушка, гидроизоляция. |
| `js/core/strip.js` | `calculateStrip` | Лента, хомуты и свайное поле. |
| `js/core/walls.js` | `calculateWalls` | Блоки и кирпич, проёмы, перемычки, армопояс, перегородки. |
| `js/core/floor.js` | `calculateFloor` | Деревянные балки или железобетонные плиты. |
| `js/core/plaster.js` | `calculatePlaster` | Гипс или ЦПС, грунтовка, маяки, сетка. |
| `js/core/roof.js` | `calculateRoof` | Односкатная, двускатная и вальмовая геометрия, стропила, обрешётка, покрытие. |

UI плиты и ленты — `js/ui/slab.js`, `js/ui/strip.js`. Остальные потоки, сводная, JSON, анкета и запуск — `js/app/*.js`. Сводная собирается в `js/app/summary.js` по чекбоксам разделов.

`PRODUCT_SPEC.md` фиксирует контрольный эталон сводной «плита + legacy-стены + материалы штукатурки»: **19 678,29 Br**. Видимая сводная на актуальной геометрии — другой контракт (**23 036,47 Br** и **23 236,77 Br** в `docs/regression-baseline.md`). Тесты держат оба числа раздельно.

### Сервер

Это рабочий Node.js HTTP-сервер, не пустая заготовка. Точка входа: `server/server.cjs`. Перед запуском: `node server/db-migrate.cjs`.

Уже есть:

- статика репозитория и `POST /api/project-check` (размер и SHA-256, без сохранения);
- `POST /api/projects/migrate` и `GET /api/projects/:id` с capability token и SQLite;
- файлы PDF/DOCX: upload, list, download, preview, apply-ack, delete;
- лимит JSON 1 МиБ, файла 5 МиБ, не больше 20 файлов на проект;
- blob вне web root (`data/blobs/<objectId>`), статический URL блобов отдаёт 404;
- миграции `server/migrations/001_init.sql` и `002_file_objects.sql`;
- публичный контур тестеров описан в `docs/DEPLOY_FORNEX.md`: `http://31.172.78.193/`, systemd, env вне Git. На сервер Chromium не ставится.

Клиент этого API: `js/app/server-access.js`, `backend-check.js`, `project-migration.js`, `document-import.js`.

## Заготовки под PDF и Gemini API

Загрузка PDF и превью фактов уже реализованы. Вызова Gemini в коде нет.

Что есть:

- UI в `index.html`: поле «Загрузить PDF или DOCX», iframe просмотра PDF, текстовый preview DOCX, таблица фактов со статусами «найдено / вручную / проверка / конфликт».
- Парсер явного текста: `js/app/explicit-text.js`, сервер реэкспортирует его из `server/import/explicit-text.cjs`. Читаются текстовые литералы PDF и `word/document.xml`. Картинки чертежа не распознаются.
- Факты с evidence: `js/app/extracted-facts.js`, схема `smetacraft-extracted-facts/1`. Модуль не пишет в DOM и не вызывает `js/core`.
- Применение: `js/app/document-import.js` пишет в поля только отмеченные строки. Ошибка любого выбранного факта отменяет весь пакет.
- Если текстового слоя нет, создаётся факт `document.ocr_required` с предупреждением «Локальный OCR не подключён. Платные API не вызываются.» Галочка на нём не стоит.
- `createLocalOcrAdapter()` возвращает `{ name: "none", available: false }` и причину `local_ocr_not_installed`.
- Эталон разметки без исходных PDF: `data/training/annotations/v0.1`.
- Аудиты Phase 8 (`docs/PHASE_8_GEMINI_AUDIT.md`) — это отчёт Gemini Notebook по поведению, а не интеграция API.

Чего нет:

- клиента Google AI Studio / Gemini Vision;
- переменных `GEMINI_API_KEY` или имени модели в `server/config.cjs`;
- маршрута, который отправляет PDF во внешний API;
- выбора страниц перед отправкой и миниатюр страниц;
- JSON-схемы ответа модели в коде.

`docs/CURSOR_AUTONOMOUS_DEVELOPMENT_PROMPT.md` описывает желаемый следующий шаг (VPS, PM2, Nginx, Gemini, выбор страниц, таблица «Preview PDF facts»), но как исполняемый промпт он ещё не готов: в тексте пустые места вместо URL репозитория, имён переменных окружения, JSON-схемы, команды тестов и имени скрипта PM2. Этот промпт расходится с действующими запретами на LLM в импорте.

## Что обновить в правилах перед подключением VPS и Gemini

Сервер для тестеров уже есть: Fornex, `docs/DEPLOY_FORNEX.md`, systemd, origin `http://31.172.78.193`. Промпт про «чистый VPS в понедельник» и PM2 описывает другой контур. Его нельзя исполнять поверх текущих правил без явного решения владельца.

1. **Снять противоречие до первой строки кода.** Сейчас `AGENTS.md`, `docs/IMPORT_PDF.md`, скилл `smetacraft-pdf-facts` и раздел 10 `docs/PHASES_6_9_EXECUTION_PLAN.md` запрещают LLM в импорте. `docs/CURSOR_AUTONOMOUS_DEVELOPMENT_PROMPT.md` требует Gemini Vision. Пока скилл и план не изменены, агент обязан отказать в OCR API. Если владелец разрешает чтение чертежей, в правилах нужно одной фразой разделить роли: модель только предлагает факты; объёмы, запасы и деньги по-прежнему считает `js/core`. Факт без evidence и без галочки в калькулятор не попадает.
2. **Заполнить пустые места промпта** и привязать его к существующему preview/apply (`js/app/document-import.js`, `js/app/extracted-facts.js`), а не к новому параллельному виджету. Выбор страниц — отдельный scope, его в Phase 8 нет.
3. **Не заводить второй способ деплоя молча.** Либо новый сервер получает свой документ (хост, bind, origin, процесс), либо дорабатывается Fornex. `DEPLOY_FORNEX.md` уже выбирает systemd, а не PM2, и запрещает ставить Chromium на машину с 1 ГБ RAM. Ключ Gemini живёт только в `/etc/smetacraft.env` (права `600`), не в Git и не в браузерном JS. Клиент вызывает свой API, API вызывает Gemini.
4. **До публичного ключа закрыть дыры Phase 9, хотя бы правилом.** Phase 9 не начата: нет rate limit, квот, TLS-чеклиста, структурных логов без тела PDF и без ключа, health без утечки деталей. Иначе загруженный чертёж и ключ API окажутся на открытом `0.0.0.0` без ограничения частоты.
5. **Сохранить текущие запреты импорта.** Цены и валюта из PDF не применяются. `ocr_required` не выбран по умолчанию. Ошибка одного факта отменяет пакет. Исходные PDF в Git не класть. Golden и формулы этим этапом не трогать. После любого изменения математики — `node --test tests/golden.test.cjs`; после изменения импорта — полный `node --test tests/*.test.cjs`.
6. **Починить очистку тестов на Windows до того, как VPS-работа будет считаться проверенной локально.** Иначе провал `rmSync` маскирует настоящую регрессию upload/migrate. На Linux VPS тот же набор может быть зелёным; локальный Windows-прогон сейчас этого не доказывает.
