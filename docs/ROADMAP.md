## Точка перехода после Phase 2

В `master` подтверждены golden- и security-наборы, безопасный адаптер JSON v1, проектные скиллы и вся Phase 3. Беседа «Планирование Phase 3» была планом, а не реализацией; переход к коду состоялся позднее. Phase 3C завершила путь ручного ввода и эквивалентность DOM/JSON. Владелец согласовал модульную целевую архитектуру и доставку через HTTP(S); правило обновлено в `AGENTS.md`. Phase 4 выделила все шесть предметных расчётов в `js/core/*.js`; перенос плиты выполнен по отдельному явному разрешению.

## Правила работы по карте

- Перед каждой фазой сверять этот план с актуальными `AGENTS.md`, `PRODUCT_SPEC.md`, кодом, тестами, Git и решением владельца. Код и принятый scope имеют приоритет над устаревшим описанием.
- Для каждой фазы отдельно утверждать ограниченный scope, критерии выхода, регрессионные проверки и способ отката. Не начинать следующую фазу автоматически.
- Сохранять контракт: одинаковые вход и цены дают те же строки, количества, коэффициенты и суммы, если владелец явно не утвердил изменение поведения. Не переписывать `tests/golden.json` ради прохождения тестов.
- Phase 4 и Phase 5 постепенно разделяют расчётное ядро и frontend согласно обновлённому `AGENTS.md`. Разрешение на архитектурное направление не заменяет конкретный план, проверки и приёмку каждой фазы.
- Commit, push, PR и deploy выполнять только при отдельном разрешении для соответствующей фазы.
