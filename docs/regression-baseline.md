# Golden baseline действующих расчётов

## Запуск

Из корня репозитория: `node --test tests/golden.test.cjs`.

Проверки безопасной границы JSON и построения строк: `node --test tests/security.test.cjs`. Проверки модели и её адаптеров: `node --test tests/project-model.test.cjs`. Минимальная Node-модель DOM проверяет структуру и свойства элементов, но не работу настоящего HTML-парсера; после изменений нужен ручной браузерный security smoke-test импорта.

Нужен установленный Node.js; пакеты npm, сеть и ручной ввод не требуются. Команда запускает 21 golden-сценарий, проверку JSON формата `version: 1`, путь `localStorage`, путь анкеты с одной плитой, старый контроль и его `runRegressionTests`. Ненулевой код завершения означает расхождение с эталоном.

## Что защищено

`tests/scenarios.cjs` задаёт все параметры и цены. `tests/golden.json` содержит результаты, дважды полученные из текущего `index.html`: исходный порядок строк, отображаемые и числовые количества, коэффициенты, категории, стоимости строк, промежуточные итоги по категориям/разделам, общий итог, HTML ведомости, подписи и сообщения об ошибках. Исходный SHA-256 сохранён как происхождение эталона, но изменение самого хеша не делает тест красным: будущий перенос ядра должен сравниваться по поведению.

`tests/runtime.cjs` читает рабочие функции **непосредственно из `index.html`, `js/ui/slab.js`, `js/ui/strip.js`, `js/core/slab.js`, `js/core/strip.js`, `js/core/walls.js`, `js/core/plaster.js`, `js/core/roof.js` и `js/core/floor.js`** и исполняет их в отдельном контексте Node в порядке загрузки страницы. Он предоставляет значения форм и элементы для результата, но не содержит копий формул. Для сводной вызывается настоящий `renderSummary`, а для JSON — настоящие `collectProject`, `parseProjectText`, `resetProjectToZero`, `applyProject` и функции чтения разделов. Контроль экспортирует репрезентативный проект в JSON, очищает геометрию, меняет цену, radio, checkbox и флаг, импортирует JSON и сравнивает структуру проекта, цены, проёмы, сваи, строки и итог сводной. Функции записи проёмов и свай не подменяются. Отдельный тест вызывает настоящие `saveToLocalStorage` и `loadFromLocalStorage` с in-memory реализацией хранилища.

Нынешняя строка ведомости содержит `name`, `netLabel`, `k`, `orderLabel`, `cost`. Отдельной машинной цены **каждой** строки в ней нет: цены зафиксированы как входы сценария, без выдуманного `unitPrice` из округлённого текста количества. Категории определяются действующей функцией `classifyMaterial`; для отдельных калькуляторов это снимок классификации, хотя категории видны пользователю главным образом в сводной.

## Сценарии и факты

Покрыты плита с одной и двумя сетками; лента без свай и со сваями; стены без проёмов и с четырьмя окнами/дверью; деревянное и ЖБ перекрытия; штукатурка с вычетом и без; двускатная кровля; четыре видимые сводные, включая все пять разделов и ленту со сваями при исключённых стенах и штукатурке; пустая плита; граница 8,1 м/200 мм; ошибки шага, сечения, проёмов и площади штукатурки.

На зафиксированном наборе «плита + стены + штукатурка с вычетом проёмов» настоящий `renderSummary` показывает **23 036,47 Br**. При геометрии старого теста видимая сводная показывает **23 236,77 Br**. Старый `computeRegressionSummaryTotal` показывает **19 678,29 Br**, потому что вызывает `_calculateWallsLegacy` с прежними ценами/единицами стен и добавляет только `materialsCost` штукатурки. Это **разные контракты**; сравнивать их как один и тот же результат нельзя. Тесты сохраняют оба без исправления расхождения.

Существующий `runRegressionTests` запускается в Node с детерминированными подстановками его тестовых форм. Он проверяет известные общие суммы и граничное число стержней; новый набор дополнительно сравнивает строки и их порядок, ввод, цены, вывод и JSON round-trip.

Дымовая проверка анкеты задаёт только плиту, вызывает действующую `applyIntakeQuestionnaire`, затем `renderSummary`: проверяет перенесённые параметры, строки и сумму плиты, подпись рассчитанной части и список исключённых частей. Это функциональный тест на модели элементов, без кликов и визуальной проверки страницы.

## Как обновлять эталон

Команда `node tests/capture-golden.cjs` дважды снимает результаты и проверяет их повторяемость, **не записывая файл**. `--write` создаёт эталон только при его отсутствии. `--write --replace` перезаписывает его; применять это лишь в отдельной задаче после разбора каждого изменившегося значения. Нельзя обновлять эталон только ради зелёного теста.

## Предел проверки

Это проверка функций текущего приложения с минимальной Node-моделью DOM, а не пиксельный тест браузера и не проверка системного диалога печати или загрузки файла. Подтверждённый путь импортированного JSON через строки проёмов и свай к `innerHTML` устранён: строки создаются через DOM API. Security-тесты проверяют опасные строки и некорректные структуры, но Node-модель не заменяет ручной тест в настоящем браузере. Общий `billBodyEl.innerHTML` в Phase 2 не рефакторился, поскольку прямой путь импортированного свободного текста к нему не был доказан. Встроенный браузер ранее заблокировал локальный `file://` адрес; обход его политики в тестах не используется. Нужен отдельный браузерный smoke-test первого экрана, анкеты, импорта, печати и фактического выбора файла.
