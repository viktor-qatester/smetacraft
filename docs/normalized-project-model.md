# Phase 3: контракт NormalizedProjectModel и граница JSON

Модель — временный чистый снимок данных на границах приложения. Её функции `projectV1ToModel` и `modelToProjectV1` живут в `index.html`. Phase 3A ввела адаптеры, Phase 3B подключила границы JSON, Phase 3C добавила общий путь DOM → модель → DOM. `schemaVersion: 1` относится только к модели; внешний JSON сохраняет `format: "smetacraft-project"` и числовую `version: 1`.

## Полная карта полей JSON v1

Исполняемая карта `MODEL_FIELD_SPEC` в `index.html` перечисляет каждый из 99 разрешённых `PROJECT_FIELD_IDS` ровно один раз. Семь групп: `slab` (9), `strip` (9), `walls` (10), `plaster` (7), `floor` (7), `roof` (12) и `prices` (45). Идентификатор внутри группы пока совпадает с ключом v1, чтобы исключить потерю данных на переходе. Тест проверяет точное равенство карты и репрезентативного экспорта. Группы `openings` и `piles` сохраняют порядок и валидированные поля строк.

Единицы строительных полей заданы у каждого ID в карте: `m` — метр, `mm` — миллиметр, `count` — число штук/слоёв/сторон, `text` — выбранное текстовое значение или enum. Для цен единица после `:` означает `Br` за `m`, `m2`, `m3`, `kg`, `piece`, `roll`, `bag` или `can`. Эти единицы сверены с таблицей прайса в `index.html`; они описывают текущий UI, а не новые нормы расхода.

Все 15 checkbox и radio `summary-found-type` находятся в `scope`. Семь ручных флагов размеров и `lastFoundationBlock` находятся в `relationships`: они управляют источником связанных размеров. `block`, `billBlock`, `roofNeedsCalc`, `floorNeedsCalc` находятся в `viewState`. Остальные данные модели — параметры и цены; формул в ней нет.

Каждое поле представлено ячейкой `{ state, value, raw, unit, applicable }`. `known` означает разобранное значение, включая числовой ноль. `unknown` означает отсутствующий ключ либо пустую строку; наличие пустой строки сохраняется через `raw`. `unparsed` сохраняет текст, допустимый внешней схемой v1, но не являющийся числом. `applicable: false` пока определяется только для выключенного утепления кровли и отключённых перегородок; значение при этом не удаляется. Адаптер восстанавливает исходный тип и написание поля из `raw`, поэтому `"10.0"` и `"3,20"` не становятся другими строками.

`validateProjectV1` перед преобразованием сохраняет действующие правила: неизвестные top-level и секционные ключи игнорируются, известный ключ неверного типа отклоняется, массивы ограничены 500 строками, `opening.locked` сохраняет явный boolean и использует fallback только при отсутствии. Старые `w/h/n` приводятся к `width/height/count` тем же валидатором. `pile.locked` следует действующему правилу первой строки и не копирует поведение проёмов. Обратный адаптер также проходит `validateProjectV1`.

## Граница с реальным DOM

`collectProject()` читает все `input[id]` и `select[id]`, а `validateProjectV1` допускает фиксированный allowlist. Анкета и часть прайс-листа имеют дополнительные ID; динамические строки проёмов и свай тоже могут попасть в `fields`. Экспорт и автосохранение сохраняют эти DOM-only ключи в `compatibility.domExtras` снимка модели и возвращают их в JSON. При импорте неизвестные ID по-прежнему игнорируются. Это сохраняет действующую асимметрию v1; Phase 3B не объявляет лишние ключи частью нормализованной схемы.

Phase 3C ввела `projectModelFromDom()` для снимка ручного ввода и `applyProjectModel()` для восстановления DOM. Экспорт и автосохранение используют первый путь; файл и `localStorage` читаются в модель через `parseProjectModelText()` и передаются второму. Совместимые функции `collectProject()`, `parseProjectText()` и `applyProject()` остаются доступными для старого кода. Модель не хранится как второй изменяемый глобальный объект. Расчётные `read*Form` и формулы пока читают DOM, как раньше.

## Проверка и границы

`tests/project-model.test.cjs` проверяет полное покрытие 99 ID, двустороннее преобразование, строки цен, отсутствие и ноль, отключённое значение, порядок строк, `locked`, aliases и версии. Для Phase 3B добавлены проверки DOM-only ID и незаполненной строки. Для Phase 3C сравниваются модели от ручного ввода и JSON, полное восстановление DOM и отказ от некорректной модели до изменения состояния. Существующие golden/security тесты защищают расчёты, JSON, `localStorage` и безопасность. Формулы, UI и `tests/golden.json` не менялись.
