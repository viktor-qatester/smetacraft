# AGENTS.md: ПРАВИЛА И СИСТЕМНЫЕ НАВЫКИ ПРОЕКТА SMETACRAFT

Этот документ задаёт правила разработки для всех задач и файлов репозитория. Последовательность фаз и их статус определяет `docs/ROADMAP.md`; каждую фазу выполнять в отдельно согласованном scope.

---

## 1. ФУНДАМЕНТАЛЬНЫЕ ПРИНЦИПЫ (AGENT SKILLS PROTOCOL 2026)

1. Process over Prose (Процесс вместо прозы):
   - Никаких пространных рассуждений. Каждая задача выполняется по строгому сценарию с детерминированными критериями завершения (Exit Criteria).

2. Scope Discipline (Дисциплина границ):
   - Трогать строго то, о чем прямо попросили.
   - Готовые модули менять только в пределах утверждённого шага. Phase 4 завершила выделение расчётного ядра; её принятие не разрешает менять формулы в следующих фазах.

3. Anti-Rationalization (Таблица запретов и отговорок):
   | Типичная отговорка агента | Жесткое системное правило |
   | :--- | :--- |
   | «Разделю весь код сразу и заодно перепишу расчёты» | Phase 5 разделяет frontend постепенно по `docs/ROADMAP.md`, с неизменным расчётным контрактом и проверками после каждого шага. |
   | «Оставлю заглушку // TODO для формул» | Запрещено. Все строительные формулы и коэффициенты пишутся сразу. |
   | «Сделаю приблизительный расчет/Math.random» | Запрещено. Вся математика детерминирована, проверена нормами расхода. |
   | «Добавлю вызов LLM API для подсчета» | Запрещено. Расчет материалов стоит 0 токенов (чистый JavaScript в `js/core`). Gemini Vision API допускается только как чтец PDF, не как калькулятор. |
   | «Запишу распознанное сразу в поля калькулятора» | Запрещено. Факты попадают только в таблицу Preview PDF facts и записываются после явной галочки пользователя. |
   | «Положу GEMINI_API_KEY в браузерный JavaScript или в Git» | Запрещено. Ключ только на сервере в `.env` или `/etc/smetacraft.env`. `.env`, файлы ключей и загруженные PDF в Git не коммитить. |

4. Non-Negotiable Verification (Бескомпромиссная верификация):
   - Задача не считается закрытой со слов «я всё сделал». 
   - Любое изменение калькулятора обязано сопровождаться контрольным расчетом: ввод контрольных данных -> сверка с итоговой таблицей ведомости.

5. Progressive Disclosure (Поэтапное раскрытие):
   - Контекст держится чистым. В Phase 5 выделять один пользовательский поток frontend за шаг, с отдельной проверкой после каждого шага.

6. Skill maintenance (Актуальность навыков):
   - После приёмки фазы и перед планом следующей применять `smetacraft-skill-maintenance`: сверять скиллы с кодом и тестами, исправлять только устаревшие повторяемые инструкции. Статус фаз записывать в `docs/ROADMAP.md`, не в скиллы.
   - Памятка владельцу по созданию и применению скиллов — `docs/SKILLS_GUIDE.md`.

## 2. АРХИТЕКТУРА И СТЕК (SMETACRAFT)
- Архитектура: `Calculation Core` в `js/core/*.js`, frontend-логика в `js/ui/*.js` и `js/app/*.js`, разметка и стили в `index.html`. Phase 5 разделила frontend по потокам без изменения расчётного контракта; порядок загрузки и зависимости описаны в `docs/FRONTEND_MODULES.md`. Не выполнять полный перепис приложения одним изменением.
- Приложение доставляется пользователю через HTTP(S). Открытие автономного `index.html` через `file://` не является обязательным контрактом. Локальный сервер остаётся способом разработки и проверки. Backend появляется в Phase 6, а не автоматически при выделении frontend-модулей.
- `localStorage` и JSON v1 сохраняют действующее поведение до согласованной миграции Phase 7. Не удалять локальные проекты автоматически; перенос данных должен быть проверен отдельно.
- Интерфейс: Двухколоночный утилитарный лейаут (параметры слева, закрепленная ведомость материалов справа).
- Дизайн: Строгий инженерный UI без лишних декоративных теней, раздутых отступов и псевдостиля.
- Математика: Детерминированные функции в `js/core/*.js`. Объёмы, нахлёсты арматуры, запасы и итоговая стоимость считаются без LLM. Округление до целых хлыстов/мешков/рулонов, нормативные запасы (бетон 5%, арматура нахлест 40d, гидроизоляция 15%). Перенос кода не разрешает менять формулы, строки или суммы ведомости. Gemini Vision API не подменяет эти функции.
- Проверка каждого шага: актуальные golden, security и model-тесты, контрольный ввод со сверкой строк и итога ведомости, браузерная проверка через HTTP(S). `tests/golden.json` не обновлять ради прохождения тестов.
- Задача, которая меняет приложение, считается опубликованной только после проверки двух мест: GitHub Pages (`https://viktor-qatester.github.io/smetacraft/`) и приложения на AEZA. На обеих страницах должен быть один и тот же номер релиза. Публикация выполняется командой `node scripts/publish.cjs` из [docs/RELEASE.md](docs/RELEASE.md). Если доступа к серверу AEZA нет, прямо сообщить: «В GitHub сохранено, на AEZA не опубликовано» и дать команду `node scripts/publish.cjs --aeza-only`. Ответ HTTP 200 эту проверку не заменяет.
- Серверные `.env`, каталог `data/` и резервные копии не выравниваются между окружениями и не попадают в Git. FORNEX остаётся прежним окружением для отката; команда публикации его не обновляет и не запускает `scripts/install-fornex.sh`.
- Commit, push, PR и deploy — только при отдельном разрешении владельца. Не начинать следующую фазу автоматически. Не делать force push.

## 3. GEMINI VISION API: ЧТЕЦ ЧЕРТЕЖЕЙ, НЕ КАЛЬКУЛЯТОР

1. Разделение ролей:
   - РАЗРЕШЕНО (ИИ как чтец/OCR): использовать Gemini Vision API через прокси-запросы бэкенда Node.js на VPS исключительно для чтения и извлечения геометрических параметров, марок материалов и спецификаций из инженерных PDF-чертежей.
   - СТРОГО ЗАПРЕЩЕНО (детерминированность): доверять ИИ вычисление объёмов, нахлёстов арматуры, запасов и итоговой стоимости. Вся математика и калькуляция сметы выполняются строго детерминированным JavaScript-кодом в `js/core/`.
   - Human-in-the-Loop: распознанные ИИ данные попадают только в таблицу временного превью («Preview PDF facts»). Ни один факт не записывается в калькулятор без явной простановки галочки пользователем.

2. Безопасность ключей:
   - Переменная `GEMINI_API_KEY` хранится только на сервере в `.env` или `/etc/smetacraft.env` и никогда не передаётся в браузерный JavaScript.
   - Запрещено коммитить `.env`, файлы ключей и загружаемые пользователями PDF-файлы в Git.
