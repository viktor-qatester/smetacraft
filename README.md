# Smetacraft

Smetacraft — автономный веб-конструктор ведомостей материалов для строительства. Текущая версия рассчитывает плитный и ленточный фундаменты, стены, штукатурку, кровлю, перекрытия и сводную смету объекта.

## Запуск

Разместите `index.html` вместе с каталогами `js/core`, `js/ui` и `js/app` на статическом HTTP(S)-хостинге и откройте страницу в современном браузере. Расчёты, локальное сохранение, импорт и экспорт работают без сервера. Для проверки серверного приёма нужен локальный сервер ниже. Порядок frontend-файлов описан в [docs/FRONTEND_MODULES.md](docs/FRONTEND_MODULES.md).

Для локальной проверки серверного приёма проекта запустите `node server/db-migrate.cjs`, затем `node server/server.cjs` и откройте `http://127.0.0.1:8000/`. Публичный контур testers — VPS Fornex (`http://31.172.78.193/`), см. [docs/DEPLOY_FORNEX.md](docs/DEPLOY_FORNEX.md). GitHub Pages не является продом API и PDF/DOCX.

## Анкета для заказчика

Вкладка **«Мой дом»** — простые вопросы без JSON: длина и ширина дома, высота стен, число окон и дверей, что включить в смету. Кнопка **«Посчитать смету моего дома»** подставляет параметры и открывает сводную ведомость справа.

## Работа с данными

- параметры проекта автоматически сохраняются только в браузере текущего устройства;
- «Новый проект» очищает геометрию и дополнительные опции, но сохраняет цены прайс-листа;
- «Экспортировать проект» скачивает JSON-файл со всеми параметрами;
- JSON-файл можно загрузить обратно в браузер без передачи данных в сеть;
- печать ведомости открывает системный диалог браузера, где её можно сохранить в PDF.

## Методика и границы расчёта

Формулы расчёта детерминированные: без ИИ и без внешних сервисов. В них учтены запасы, нахлёсты арматуры, округление до единиц закупки и другие параметры, перечисленные в [PRODUCT_SPEC.md](PRODUCT_SPEC.md).

Это предварительная ведомость закупки, а не проектная документация. До строительных работ проектировщик должен проверить нагрузки, грунты, защитный слой бетона, армирование, гидроизоляцию и применимые местные нормы. Цены следует сверять с поставщиком.

## Проверка перед публикацией

После открытия страницы в правой части интерфейса должен появиться статус успешных регрессионных тестов. Один из контрольных случаев проверяет, что при пролёте 8,1 м и шаге 200 мм расчёт учитывает край и возвращает 42 стержня на одну сетку.

Независимый golden-набор запускается из корня репозитория одной командой: `node --test tests/golden.test.cjs`. Он сравнивает действующие строки ведомости, количества, цены и итоги, включая JSON export/import. Сценарии и ограничения описаны в [docs/regression-baseline.md](docs/regression-baseline.md).

## Дальнейшее развитие

Порядок и текущий статус запланированных фаз 1–9 приведены в [дорожной карте](docs/ROADMAP.md).

Будущий импорт исходных документов (PDF, DOCX, таблиц, изображений и чертежей) стоит реализовывать отдельным серверным модулем: сервис извлекает возможные параметры, а пользователь обязательно подтверждает их перед расчётом. Это защитит смету от ошибок распознавания.
